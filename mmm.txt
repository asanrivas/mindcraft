● For SSH sessions in Ghostty, the clipboard issue is because the remote server doesn't have access to your local clipboard.

  Best solution for Ghostty + SSH:

  Ghostty supports OSC 52 escape sequences for remote clipboard access. You can use a simple script on the remote server:

  # Add to ~/.bashrc on remote server
  copy() {
    printf '\033]52;c;%s\a' "$(base64 | tr -d '\n')"
  }

  Then pipe output to it: echo "text" | copy

  For Claude Code specifically:

  The /export command tries to use xclip/wl-copy which don't work over SSH. Your options:

  1. Manual copy - Just select the text in Ghostty and copy (Cmd+C on Mac)
  2. Use /export with file output - The conversation is also saved to a file, check:
  ls -la /tmp/claude-export* 2>/dev/null || echo "Check Claude Code docs for export location"
  3. Install xclip anyway (won't fix SSH but stops the error):
  sudo apt-get install xclip

  Recommendation: For Ghostty + SSH, just manually select and copy - Ghostty handles this well. The OSC 52 solution is more complex and Claude Code doesn't use it natively.
